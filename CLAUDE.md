# Budget 2.0

A personal finance Streamlit app for visualizing, sorting, and filtering expenditures across multiple bank and credit card accounts. Runs in Docker. **Claude does not run Python — the user runs `docker compose up --build` to launch the app.**

## Stack & structure

```
src/
  app.py                  # Streamlit entry point; runs preprocessing once per session
  preprocessing.py        # Ingests raw CSVs → expenditures.csv + visual_expenditures.csv
  categoricals.py         # Lists: EXPENDITURE_CATEGORIES, ALL_SUBCATEGORIES, NECESSITY
  pages/
    expenditures.py       # "Expenditures" tab
    create_transaction.py # "Create Transaction" tab
    pie_charts.py         # "Pie Charts" tab
rawdata/
  alliant_cc/
  alliant_checking/
  chase_cc/
  chase_checking/
  discover_cc/
expenditures.csv          # generated, gitignored
visual_expenditures.csv   # generated, gitignored
```

## Data sources

Five file-based accounts under `rawdata/`, plus two manual-entry accounts:

| Key | Account |
|---|---|
| `alliant_cc` | Alliant Credit Union credit card |
| `alliant_checking` | Alliant Credit Union checking |
| `chase_cc` | Chase Bank credit card |
| `chase_checking` | Chase Bank checking |
| `discover_cc` | Discover credit card |
| `Cash` | Manual cash transactions |
| `Crypto` | Manual crypto transactions |

`Cash` and `Crypto` transactions are entered via the Create Transaction page and written directly to `expenditures.csv`; they have no raw data files.

## expenditures.csv

Generated by `preprocessing.py` on every app startup. New raw files can be dropped into `rawdata/` at any time; duplicate transactions (same date + amount + description) are never imported twice. Manually created transactions are appended directly and are not re-processed.

Columns: `date`, `amount`, `description`, `account`, `category`, `subcategory`, `necessity_level`, `timescale`, `timescale_end`, `ignore`

- `category`, `subcategory`, `necessity_level` — blank by default, set by the user in the app
- `timescale` / `timescale_end` — default to `date`; user can widen the range to spread a transaction across multiple days in visual_expenditures.csv
- `ignore` — boolean (default `False`); transactions marked `True` are excluded from visual_expenditures.csv and can be hidden in the Expenditures table

### Amount sign convention

**Negative = money going out, positive = money coming in.** Each source requires a different transform:

| Account | Raw: money out | Transform |
|---|---|---|
| `alliant_cc` | `$16.82` (positive) | multiply by -1 — plain dollar = purchase on a CC statement, opposite of checking |
| `alliant_checking` | `($16.82)` (parens) | none — `_parse_alliant_amount` returns negative for parens |
| `chase_cc` | `-16.82` (negative) | none — already correct |
| `chase_checking` | `-16.82` (negative) | none — already correct |
| `discover_cc` | `16.82` (positive) | multiply by -1 |

Alliant exports HTML entities in descriptions (`&#39;` → `'`, `&amp;` → `&`). Both Alliant loaders call `html.unescape()` on the description field.

## visual_expenditures.csv

Fully derived from `expenditures.csv`; regenerated on every run. Columns: `date`, `amount`, `category`, `subcategory`, `necessity_level`.

Each transaction is spread evenly across its `timescale`→`timescale_end` date range. A $100 transaction spanning 5 days becomes five $20 rows, one per day. Transactions with `ignore=True` are excluded. Used as the data source for all visualization pages.

## Categoricals (`categoricals.py`)

- `EXPENDITURE_CATEGORIES` — top-level categories (e.g. `transport`, `groceries`, `eating out`)
- `ALL_SUBCATEGORIES` — subcategories in `"category:subcategory"` format; always filtered to the selected category before being shown to the user
- `NECESSITY` — necessity levels: `basic`, `middle`, `luxury`, `donation`, `investment`

## Streamlit app

`app.py` uses `st.navigation` for left-side tab navigation. Pages live in `src/pages/`. Preprocessing runs once per browser session via `st.session_state`.

### Persistent session state keys

These are set on the Expenditures page and read by all other pages — never hardcode date or filter defaults, always use these keys:

| Key | Type | Description |
|---|---|---|
| `date_start` | `datetime.date` | Start of the active date filter |
| `date_end` | `datetime.date` | End of the active date filter |
| `filter_categories` | `list[str]` | Selected category filter values |
| `filter_necessity` | `list[str]` | Selected necessity level filter values |

### Expenditures page

Editable table of `expenditures.csv`. Filters (all persistent via session state):
- Date range (From / To) — `date_start` defaults to earliest date in data; `date_end` defaults to today's date
- Category multiselect
- Necessity Level multiselect
- "Hide Ignored Transactions" checkbox (default on)
- "Show Only Uncategorized" checkbox — shows only non-ignored transactions missing a `category` or `necessity_level`

Editable columns: `category` (SelectboxColumn), `subcategory` (SelectboxColumn), `necessity_level` (SelectboxColumn), `ignore` (CheckboxColumn). All other columns are read-only. Changes are saved explicitly via the "Save Changes" button.

### Create Transaction page

Manual entry form for `Cash` and `Crypto` transactions. Fields: date, amount, account, description, category, subcategory (filtered by category), necessity level. Appends directly to `expenditures.csv`. Description is the only required field.

### Pie Charts page

Two full-width stacked pie charts sourced from `visual_expenditures.csv`, both respecting all persistent filters. Only spending (negative amounts) is shown, converted to positive for display. Blank category/necessity_level shown as "Uncategorized"/"Unassigned".

Controls above the charts (in order):
1. **Time Scale dropdown** — `Total`, `Per Day`, `Per Week`, `Per Month`. Divides all amounts by the number of days/weeks/months in the active date range. Per-Month uses 30.4375 days as the average. Updates chart titles and the total label accordingly.
2. **Total spending display** — large-font label showing the scaled total (e.g. "Per-Day Spending: $X.XX").

Charts:
- **Spending by Category**
- **Spending by Necessity Level**
